01 — Thesis

The question
matters.

Classic service-mesh security answers a simple question: "is this connection from a trusted host?" That is necessary — but not sufficient for LLM-driven agents, where the threat is often a legitimately authenticated agent that has been prompt-injected, confused-deputied, or driven into a runaway loop.

SAACP adds the agent-specific layer on top of transport security: authorization invariance, intent envelopes, injection scanning, epistemic circuit breakers, and causal-graph governance.

Design principle → Reordering the gate pipeline is treated as a security bug. Tiers affect telemetry verbosity — never which checks run. Every packet traverses every gate. No exceptions.
02 — Protocol

Twelve primitives,
one invariant pipeline.

The complete cryptographic and governance stack. Each primitive is a load-bearing element — remove one and the invariant collapses.

01
MEASC

Per-frame AEAD

Every frame is AES-256-GCM encrypted with keys derived per (session, epoch, packet-sequence-number) via HKDF-SHA256. The 128-byte transport header is authenticated as AAD — tamper any bit and decryption fails closed.

AES-256-GCM16-byte tagHKDF-SHA256
02
Ratchet

Forward-secret key evolution

Session keys ratchet forward by epoch, triggered by time threshold or packet count. Compromise of one epoch exposes neither past nor future traffic.

HKDF-SHA256X25519 ECDH
03
Invariant

Authorization invariance

All twelve mandatory gates execute on every packet regardless of tier. Tiers govern telemetry verbosity, never enforcement. Reordering is a bug.

Non-reorderable
04

Capability tokens

Ed25519-signed, action-class ceiling, delegation depth capped at three hops.

Ed25519ed25519-dalek
05

Injection scanning

NFKC normalization, 300+ confusable homoglyphs, Aho-Corasick across three decode layers.

Aho-CorasickNFKC
06

Immutable audit

HMAC-authenticated hash-chain with WAL batching fsync. Every decision provably recorded.

WALHMAC-SHA256

Replay protection

4,096-entry sliding PSN window with anomaly detection and quarantine.

HRT

Hardware Root of Trust

Signing keys can live inside hardware that never releases them — PKCS#11 HSMs, AWS KMS Ed25519, GCP Cloud KMS. Seamless software fallback when hardware is absent.

06 — Module map

~50 Rust modules,
one coherent system.

Core protocol, identity/trust frameworks, transport, runtime, and observability — each module a single responsibility.

framing.rs
Wire formats
MEASC (128-byte) + SAACPFrame (101-byte) wire formats, AES-GCM, Adler-32, zlib compression.
measc.rs
Session epochs
HKDF key evolution, replay window, packet sequencing — the transport-layer frame carrying all live traffic.
handler.rs
Gate pipeline
SAACPProtocolHandler — the full twelve-gate pipeline and prompt-injection scanner. Non-reorderable.
daemon.rs
Network daemon
SAACPNetworkDaemon — async listener, per-IP circuit breakers, timeouts, active-active clustering.
acsvaf.rs
Capability tokens
Ed25519 capability token issuance and verification authorities. Action-class ceilings, delegation caps.
faitf.rs
Federated identity
Federated Agent Identity & Trust Framework — revocation, mesh federation, delegation chains across orgs.
factf.rs
Capability transparency
Federated Agent Capability Trust Framework — threshold tokens, transparency log, risk-aware authz.
gateway.rs
Zero-trust gateway
ZeroTrustGateway, AgentRateLimiter, delegation guard, RRBC gateway logic.
hrt/
Hardware Root of Trust
PKCS#11, AWS KMS, GCP KMS, Remote Key Server backends. Seamless software fallback when absent.
cluster.rs
Active-active sync
Multi-daemon node clustering, heartbeats, cross-datacenter DRI revocation propagation.
sidecar.rs

Local HTTP proxy — plain JSON ⇄ SAACP-secured traffic. Zero protocol knowledge required.
command_center.rs
Dashboard backend
REST + SSE API for live trust mesh, attack feed, financial circuit breaker metrics. Axum-powered.

08 — Integration

Three surfaces,
one protocol.

Native Rust, Python SDK, or plain HTTP sidecar. Pick the surface that fits — the protocol underneath is identical.

Cargo.toml
[dependencies]
saacp = "0.1"
tokio = { version = "1", features = ["rt", "rt-multi-thread", "net", "io-util", "time", "macros", "sync"] }

[features]
# Every optional transport / backend is behind a flag
default = []
transport-ws = ["dep:tokio-tungstenite"]
transport-tls = ["dep:tokio-rustls", "dep:rustls-pemfile"]
redis-backend = ["dep:redis"]
hrt-pkcs11   = ["dep:cryptoki"]
hrt-aws-kms  = ["dep:aws-sdk-kms", "dep:aws-config"]
hrt-gcp-kms  = ["dep:gcloud-sdk"]
command-center = ["dep:axum", "dep:futures-util"]
agent.py
from saacp import wrap, SidecarManager

# Wrap any LangChain / AutoGen / custom agent
# Sidecar handles the SAACP wire — agent stays plain Python
manager = SidecarManager(port=8080)
agent = wrap(my_agent, sidecar=True, tier="standard")

# All 12 gates, zero protocol knowledge required
response = agent.send(peer, "plan the next step")

# Lifecycle management + health monitoring included
manager.monitor(agent)
terminal
# 1. Start the sidecar proxy
$ saacp-sidecar --port 8080 --gateway "tcp://gateway:7444"

# 2. Agent speaks plain HTTP/JSON — zero protocol knowledge
$ curl http://localhost:8080/send \
    -H "Content-Type: application/json" \
    -d '{"to":"agent-42","msg":"verify identity","ttl":30}'

# 3. Response: full gate-pipeline result with audit hash
# {"status":"delivered","gate_events":[...],"audit_hash":"7f3a...c2e1"}
